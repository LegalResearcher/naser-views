# Naser Views

يسحب منشورات قناة `@muen2025` ويعالج روابطها مباشرة عبر GitHub Actions؛ التشغيل الرئيسي وإعادة الرابط المحدد لا يعتمدان على طابور Other أو OIDC.
جدولة Supabase المستقلة مفعّلة لاستدعاء `run-standalone.yml` بفاصل فعلي 60 دقيقة (يُفحص الاستحقاق كل دقيقة، وقد يتأخر الإرسال حتى دقيقة عن الموعد).

## الإعداد
1. أضف بيانات الدخول في Settings > Secrets and variables > Actions > New repository secret:
   - `SITE_USERNAME_1` و`SITE_PASSWORD_1` — بيانات الحساب الأول
   - `SITE_USERNAME_2` و`SITE_PASSWORD_2` — بيانات الحساب الثاني
   - `SITE_USERNAME_3` و`SITE_PASSWORD_3` — بيانات الحساب الثالث
2. في Supabase Vault أضف سر GitHub باسم `github_actions_token`، ويجب أن يملك صلاحية تشغيل Actions للمستودع.
3. تشغيل الروابط الجديدة يدويًا: Actions > Naser Views أو Naser Views Standalone > Run workflow.
4. إعادة رابط محدد يدويًا: Actions > Naser Views - Manual Link Retry.

لا يمكن التحقق من وجود أسرار Actions في إعدادات المستودع من بيئة التطوير الحالية؛ يلزم التأكد من إضافة الأسرار الستة بالأسماء أعلاه داخل إعدادات المستودع. لا تُحفظ قيمها أو تُطبع.

## كيف يعمل
- عند وجود روابط جديدة، تُعالج أولاً من الأحدث إلى الأقدم، ثم روابط الدفعة السابقة من الأحدث إلى الأقدم. عند غياب الجديد، تُعالج أولاً الروابط التي لم يسبق أن جرت محاولة لها؛ وبعدها تُعالج مجموعات ثابتة من خمسة روابط بدءاً بالأحدث، وتُستكمل المجموعة قبل الانتقال للأقدم.
- تُحفظ الروابط المكتشفة لتجنب إدخالها ثانيةً بوصفها روابط جديدة.
- يرسل كل تشغيل حتى خمسة طلبات كحد أقصى.
- لكل رابط عدّاد نجاح وإخفاق مشترك بين الحسابات: يستمر حتى خمسة نجاحات، ويُتخطى بعد ثلاثة إخفاقات. عند غياب الروابط غير المجرّبة، يبقى النظام مع مجموعة الخمسة الأحدث المؤهلة حتى تكتمل أو تُتخطى.
- سجل `state/link_account_history.json` من النظام السابق يُستخدم فقط لمعرفة أن الروابط القديمة سبق أن جرت محاولة لها؛ لا يمنع إعادة المحاولة ولا يُحتسب نجاحاً.
- يختار كل تشغيل حساباً واحداً بالتتابع `1 → 2 → 3 → 1`، ويستخدمه طوال التشغيل. المؤشر محفوظ في `state/account_rotation.json`.
- ينتظر السكربت مدة عشوائية من 40 إلى 150 ثانية بين الطلبات داخل التشغيل الواحد.
- عند ترحيل روابط قديمة، يُعامل `state/done_links.txt` كسجل إنجاز تاريخي ولا يعاد تنفيذ روابطه.
- إعادة المحاولة اليدوية تستخدم عدادي النجاح والإخفاق نفسيهما، وترفض الرابط بعد خمسة نجاحات أو بعد ثلاثة إخفاقات.
- عند فشل تسجيل الدخول أو الحساب، يتوقف التشغيل الحالي برمز خروج `1` فقط؛ لا تُنشأ علامة إيقاف دائمة ولا يُعطّل workflow، وتستمر التشغيلات التالية كالمعتاد.
- لا يستخدم المشروع `state/account_pause.json`؛ فشل الحساب لا يوقف الجدولة أو التشغيل اليدوي التالي.

## تصفير الحالة
احذف ملفات الحالة داخل مجلد `state/` (ما عدا `.gitkeep`) لبدء المعالجة من الصفر.

## ملاحظة
بيانات الدخول لا تُكتب في أي ملف. المستودع عام، فملفات `state/` مرئية للجميع؛ ملف الدوران لا يحتوي إلا على رقم الحساب التالي.
