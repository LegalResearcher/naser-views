# Naser Views

يسحب منشورات قناة `@muen2025` ويعالج روابطها مباشرة عبر workflow مستقل، دون المرور بطابور Other.
جدولة Supabase الحالية متوقفة. بعد التأكيد ستستدعي `run-standalone.yml` بفاصل فعلي 45 دقيقة (يُفحص الاستحقاق كل دقيقة، وقد يتأخر الإرسال حتى دقيقة عن الموعد).

## الإعداد
1. أضف بيانات الدخول في Settings > Secrets and variables > Actions > New repository secret:
   - `SITE_USERNAME_1` و`SITE_PASSWORD_1` — بيانات الحساب الأول
   - `SITE_USERNAME_2` و`SITE_PASSWORD_2` — بيانات الحساب الثاني
   - `SITE_USERNAME_3` و`SITE_PASSWORD_3` — بيانات الحساب الثالث
2. في Supabase Vault أضف سر GitHub باسم `github_actions_token`، ويجب أن يملك صلاحية تشغيل Actions للمستودع.
3. تشغيل مباشر يدوي: تبويب Actions > Naser Views Standalone > Run workflow. تبقى workflows طابور Other منفصلة.

لا يمكن التحقق من وجود أسرار Actions في إعدادات المستودع من بيئة التطوير الحالية؛ يلزم التأكد من إضافة الأسرار الستة بالأسماء أعلاه داخل إعدادات المستودع. لا تُحفظ قيمها أو تُطبع.

## كيف يعمل
- في كل تشغيل، تُقدّم الروابط الجديدة أولاً ثم تُعالج الدفعة السابقة فقط، بترتيب الأقدم فالأحدث.
- تُحفظ الروابط المكتشفة لتجنب إدخالها ثانيةً بوصفها روابط جديدة.
- يرسل كل تشغيل حتى خمسة طلبات كحد أقصى.
- لا يُرسل الرابط أكثر من مرة على الحساب نفسه؛ يسجل الحساب للرابط قبل محاولة الإرسال في `state/link_account_history.json`.
- يختار كل تشغيل حساباً واحداً بالتتابع `1 → 2 → 3 → 1`، ويستخدمه طوال التشغيل. المؤشر محفوظ في `state/account_rotation.json`.
- ينتظر السكربت مدة عشوائية من 40 إلى 150 ثانية بين الطلبات داخل التشغيل الواحد.
- عند ترحيل روابط قديمة، يُعامل `state/done_links.txt` كسجل إنجاز تاريخي ولا يعاد تنفيذ روابطه.

## تصفير الحالة
احذف ملفات الحالة داخل مجلد `state/` (ما عدا `.gitkeep`) لبدء المعالجة من الصفر.

## ملاحظة
بيانات الدخول لا تُكتب في أي ملف. المستودع عام، فملفات `state/` مرئية للجميع؛ ملف الدوران لا يحتوي إلا على رقم الحساب التالي.
