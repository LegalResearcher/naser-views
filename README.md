# Naser Views

يسحب منشورات قناة `@muen2025` ويرسل طلبات المشاهدات للروابط المؤهلة في الطابور عبر نموذج الموقع باستخدام Playwright.

## الإعداد
أضف أسرار الحسابات الثلاثة من Settings > Secrets and variables > Actions:
- الحساب 1: `SITE_USERNAME_1` و`SITE_PASSWORD_1`
- الحساب 2: `SITE_USERNAME_2` و`SITE_PASSWORD_2`
- الحساب 3: `SITE_USERNAME_3` و`SITE_PASSWORD_3`

تشغيل رئيسي يدوي: Actions > Naser Views > Run workflow.
إعادة محاولة رابط محدد: Actions > Naser Views - Manual Link Retry > Run workflow.

## كيف يعمل
- في كل تشغيل يجلب الروابط الجديدة ويكرر طلب كل رابط حتى 7 نجاحات، أو حتى 3 إخفاقات؛ وتُسجل النتائج في ملفات الحالة.
- عند عدم وجود روابط جديدة، يستكمل التشغيل الدفعة السابقة حتى 3 نجاحات لكل رابط، بحد أقصى 5 طلبات في التشغيل.
- إذا توقف التشغيل توقفًا حرجًا قبل الوصول إلى بعض الروابط، تبقى الروابط غير المنفذة في الطابور لاستكمالها؛ الروابط التي جرت محاولة تنفيذها لا تُعاد تلقائيًا.
- عند عدم وجود روابط جديدة، لا يتوقف التشغيل مبكرًا؛ يُستكمل فحص الطابور المتبقي بالطريقة نفسها المستخدمة في مشروع الجنوب، كما يستمر التشغيل بالطابور الموجود إذا تعذر سحب الصفحة.
- عند عدم وجود روابط جديدة، يعالج النظام الدفعة السابقة بحد أقصى 5 طلبات في التشغيل، ويستمر عبر التشغيلات حتى يحقق كل رابط 3 نجاحات؛ الفشل يُسجّل ويُتخطى الرابط بعد 3 إخفاقات.
- حد 7 نجاحات للروابط الجديدة مستقل عن هدف الدفعة السابقة البالغ 3 نجاحات؛ إعادة معالجة الدفعة السابقة محدودة بـ5 طلبات في التشغيل.
- التشغيل الرئيسي وإعادة المحاولة يعملان مباشرة عبر GitHub Actions، دون طابور مركزي أو OIDC.
- يستخدم كل تشغيل رئيسي حسابًا واحدًا فقط لمعالجة جميع الروابط المختارة لذلك التشغيل.
- يُختار الحساب بالتناوب بين الحسابات الثلاثة، ويحفظ التشغيل الرئيسي والإعادة اليدوية المؤشر المشترك في `state/account_rotation.json`. بيانات الدخول لا تُحفظ في ملفات الحالة.
- الإعادة اليدوية تنفذ الرابط المحدد مرة واحدة فقط.
- يُحفظ طابور الروابط غير المنفذة في `state/telegram_links.txt`، وسجل الروابط التي سبق اكتشافها في `state/processed_links.txt`.
- يتم تسجيل الدخول وإرسال الطلب من خلال نموذج المتصفح مع النقر البرمجي على زر التأكيد لتجاوز العناصر العائمة.

## تصفير الحالة
احذف الملفات داخل مجلد `state/` (ما عدا `.gitkeep`) لبدء المعالجة من جديد.
