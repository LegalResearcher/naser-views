# Naser Views

يسحب منشورات قناة `@muen2025` ويرسل طلبات مشاهدات للروابط المؤهلة في الطابور.
التشغيل الدوري عبر Supabase `pg_cron`، الذي يرسل `workflow_dispatch` إلى GitHub Actions.

## الإعداد
1. أضف بيانات الدخول: Settings > Secrets and variables > Actions > New repository secret
   - `SITE_USERNAME_1` و`SITE_PASSWORD_1` — بيانات الحساب الأول
   - `SITE_USERNAME_2` و`SITE_PASSWORD_2` — بيانات الحساب الثاني
   - `SITE_USERNAME_3` و`SITE_PASSWORD_3` — بيانات الحساب الثالث
2. في Supabase Vault أضف سر GitHub باسم `github_actions_token`، ويجب أن يملك صلاحية تشغيل Actions للمستودع.
3. تشغيل يدوي: تبويب Actions > Naser Views > Run workflow.

لا يمكن التحقق من وجود أسرار Actions في إعدادات المستودع من بيئة التطوير الحالية؛ يلزم التأكد من إضافة الأسرار الستة بالأسماء أعلاه داخل إعدادات المستودع. لا تُحفظ قيمها أو تُطبع.

## كيف يعمل
- أول تشغيل: يأخذ أحدث منشور فقط.
- بعدها: كل منشور جديد يدخل الطابور بالترتيب، ويُنفَّذ الأقدم أولاً.
- يرسل كل تشغيل حتى خمسة طلبات كحد أقصى (سواء نجحت أم فشلت)، إلى خمسة روابط مؤهلة كحد أقصى.
- لا يكتمل الرابط بعد نجاح واحد: يعاد إدراجه في التشغيلات اللاحقة حتى يسجل خمسة طلبات ناجحة إجمالاً. يحتفظ `state/success_counts.json` بعداد نجاح مستقل لكل رابط، وتُحفظ التغييرات مباشرة بعد كل نتيجة ناجحة.
- الإخفاق لا يزيد عداد النجاح. يحتفظ `state/failed_attempts.json` بعداد الإخفاقات؛ وبعد ثلاث محاولات فاشلة يُتخطى الرابط.
- إعادة المحاولة اليدوية تستخدم عدادات النجاح والإخفاق نفسها، وترفض الرابط المكتمل تاريخياً أو الذي بلغ خمسة نجاحات أو تم تخطيه بعد ثلاث إخفاقات.
- يختار التشغيل الدوري والإعادة اليدوية حسابًا واحدًا بالتتابع `1 → 2 → 3 → 1`، ويستخدمه طوال التشغيل. المؤشر المشترك محفوظ في `state/account_rotation.json` ويحتوي على رقم `next_account` فقط؛ تتم مزامنة أحدث `main` قبل الاختيار لتجنب المؤشرات القديمة. إذا كانت بيانات الحساب المختار ناقصة، يتوقف التشغيل دون تحريك المؤشر.
- عند الانتقال من الإصدار السابق، يعامل `state/done_links.txt` بوصفه سجل ترحيل توافقياً: أي رابط فيه مكتمل ولا يعاد تنفيذه، من دون تعديل السجل أو احتساب نجاحات تاريخية غير معروفة. يبدأ العداد الجديد للروابط غير المكتملة والجديدة فقط، ويُحفظ في `state/success_counts.json`.
- يتم تسجيل الدخول إلى الموقع وإرسال الطلب من خلال نموذج المتصفح، مع النقر البرمجي على زر التأكيد لتجاوز العناصر العائمة.

## تصفير الحالة
احذف ملفات الحالة داخل مجلد `state/` (ما عدا `.gitkeep`) لبدء من الصفر. لا تحذف ملفات حالة الطابور أثناء تشغيل النظام.

## ملاحظة
بيانات الدخول لا تُكتب في أي ملف. المستودع عام، فملفات `state/` مرئية للجميع؛ ملف الدوران لا يحتوي إلا على رقم الحساب التالي.
